# Languages

The interface is available in English and, as drafts, Cymraeg, Gàidhlig and Gaeilge.
Two catalogues carry a language:

| What | Where | Checked by |
|---|---|---|
| Interface copy (buttons, labels, cards, map legend, assistant chips) | `web/messages/<locale>.json`, ICU messages | `npm run i18n:check` (key parity with `en.json`, plural forms per `Intl.PluralRules`, every key used) |
| Data labels (themes, indicators, units, presets, profile caveats, the words for each nation's area tiers) | `config/i18n/<locale>.yaml`, by id | `lix validate config` (a reviewed catalogue must be complete; a draft falls back to English) |

Both carry a `_meta` block: `status: draft` until a fluent reviewer signs it off, then
`status: reviewed` with the reviewer and date. The language switcher shows a draft as
such. The documentation pages (method, validation, sources) stay English and say so in
the chosen language.

What is not translated: place names (they come from the data in the official form,
with the Welsh, Gaelic or Irish form alongside where the data has one: OS Open Names for
places, the ONS and Commons Library files for Welsh areas, Wikidata for Scotland's and
Northern Ireland's councils and for the largest cities' names in each language
(`config/data/place_names_i18n.csv`), OpenStreetMap's `name:ga` tags and Logainm, with
a free key, for Northern Ireland's places; Tailte Éireann's boundary files for the Irish
names of Ireland's divisions and small areas, a curated list for its councils and
OpenStreetMap for its places), the licence and attribution
wording of sources, and the assistant's recorded answers for the no-key mode. The
assistant itself replies in the interface language; the fixed messages it sends when a
run fails, and the `profile_rationale*` sentences of a profile built by word matching,
are in `api/src/lix_api/agent/messages.py`. The word-matching engine's phrases in Welsh,
Gaelic and Irish are in `api/src/lix_api/services/profiles.py` (`PROFILE_RULES`,
`LOCAL_INDICATOR_WORDS`); it also reads every translated label in the data pack.

## Reviewing a draft

1. Read `web/messages/<locale>.json` and `config/i18n/<locale>.yaml` next to the English
   files. The English text is the reference; the draft was produced with the Welsh
   Government's [TermCymru](https://www.gov.wales/bydtermcymru) terminology where it
   applies; the Gaelic draft follows the Scottish Government's and Bòrd na Gàidhlig's
   usage as far as the drafter knew it, and needs a fluent reviewer most of all.
2. Check, in this order: terminology (official terms for the public bodies and
   measures), plural forms (`{count, plural, …}` must cover the language's categories;
   Welsh has six, Gaelic four), that place names, postcodes and numbers are unchanged, and that
   variables in braces are kept exactly.
3. Run `npm run i18n:check` (in `web/`) and `uv run lix validate config`.
4. Set `_meta.status: reviewed` with your name and the date, and open a pull request.
   The switcher drops the "draft" suffix with the next release.

## Adding a language

1. Add the code to `LOCALES`, `AUTONYMS` and `BCP47` in `web/lib/i18n.ts`, import its
   catalogue into `MESSAGES`, and add it to the inline detection script in
   `web/app/layout.tsx`.
2. Copy `web/messages/en.json` to the new code, translate, and set `_meta.status: draft`.
3. Copy `config/i18n/cy.yaml` to the new code and translate the labels you can; anything
   missing falls back to English.
4. Add the language to `LANGUAGE_NAMES` and, if you can, `MESSAGES` in
   `api/src/lix_api/agent/messages.py`, and its stopwords to `api/evals/evaluators.py`
   so the eval harness can tell a reply in it.
5. Add two eval cases with `state: {locale: <code>}` and `reply_lang: <code>` in
   `api/evals/cases.yaml`.
